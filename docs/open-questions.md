# Open questions

Questions the binaries and published sources have not yet answered. One entry each: the question, every route already tried, and the next route. When an entry is answered, move the finding into the owning header or chapter and delete the entry. `AGENTS.md` section 6 gives the rules.

**Routes every entry below has already taken**, so each entry lists only what it adds: the IP30 and IP35 kernel objects of `odyssey.a` (6.5.30m, every function read where the entry names it), the N32 libGLcore with its o32 and 64-bit siblings where a constant was searched, `odyssey.so`, `gfxinfo`, and both transform microcode images. **Routes no entry has taken yet**, to try in this order unless an entry says otherwise:

1. **Earlier releases.** The VPro files exist from 6.5.8 (IP30) and 6.5.14 (IP35). A changed constant or an added check between releases often names a field. No release carries richer debug information (`IRIX_FILES.md` section 5), so this is a diff of code, not of symbols.
2. **Diagnostics on other media.** The IP35 PROM and its diagnostics, and the Octane2 VPro Patches disc, may test registers the driver only writes.
3. **Published output from real machines.** `gfxinfo -v`, `hinv -v` and diagnostic transcripts for V6 to V12 boards in newsgroup and mailing-list archives.
4. **The shipped driver under an emulator.** Run it and log what it reads back and what it waits for. This shows the driver's expectation, not the board's behaviour, and is labelled so.

An entry that exhausts all five is relabelled "unknown: no shipped software or published source depends on it" in its owning file, with the routes listed, and removed here.

## Published sources, route tried (2026-10-29)

Patents, SGI manuals and white papers were searched for every open entry below; [published-sources.md](published-sources.md) holds the identity and facts of each. Result by entry, so no later reader repeats the route. Every patent fact is inferred, because no patent names the chip.

- **Colour interpolation arithmetic** (Raster rules): the patents describe perspective-corrected barycentrics from reciprocal-area-scaled edge distances, an interpolated 1/w correction, 12-bit bilerp modules and a recursive 4K x 4K subdivision. None gives widths or rounding. A numeric rebuild of the first `blend.SUM` panel with the weights, denominator, reciprocal, plane slopes or a uniform error rounded at 8 to 24 bits left the residue unchanged or worse (no variant below 1,082 of about 1,100); the stored bytes run high more often than low. Not yet tried: 12-bit colour modules and subdivision-order evaluation.
- **Texture arithmetic**: the quad level of detail is the base-2 logarithm of the larger diagonal difference of s and t (inferred). Filter-weight and sub-texel widths are in no published source.
- **Remaining operation codes**: the patents' scalar stage has an inverse square root, a negate, an exponent and an arc-sine; three of those match codes already read. Which table function codes 3 and 0xb are stays open: the exponent or the arc-sine.
- **Value-3 marks and the loop entries**: the patents say the transform engine has no run-time branch and runs fragments chosen from a program table. A mark deciding between two entries is more likely a table-building step. Not established.
- **Raster tie rule on a shared edge**: a patent says each shared subpixel has exactly one owner, decided by consulting the neighbouring pixels of the quad; which side is not stated.
- **3D checkerboard frame, DMA engine, display bit fields, board memory organisation, ID word, user windows**: no published source reaches them. The diagnostic reference lists seven register names the register test walks and gives the chip's clock (266 MHz), SDRAM clock (133 MHz) and on-chip memory (1.5 million bits); neither moves an entry.

## Raster rules

- **The large 3D checkerboard frame's list value.** `checkr3d.sml` now matches `csumlist.sml` (`docs/raster.md`, "Texturing"); `checkr3d.SUM` gives CRC-32 0x1f9ba6f3 against `csumlist` 0x2bb8d20c, so the file and the list come from different simulator runs. - **Antialiased points and lines.** `aapts` and `aalines` are not fitted.
