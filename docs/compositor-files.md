# Compositor install files

The `STINGRAY` files are the compositor's firmware images, the list of their versions, the program that writes them to the compositor's flash and a list of display formats. Release IRIX 6.5.30m. Every entry is **established** from the file named (read in full, or for the two large images decoded end to end by a parser written for this page), except where it says **inferred**. The updater program's routines have entries in [vpro-tool-functions.md](vpro-tool-functions.md); the format and combination files are in [display-files.md](display-files.md).

- `usr/gfx/STINGRAY/bin/cmp_flash`: **established.**
  The updater for the programmable-logic images in the compositor's flash, an N32 executable with entry `__start` at 0x10002350 and its driver `main` at 0x10002760. It parses the options `Fhnqs:u:v` (force, dry run, print versions, delay, USB device, verbose), requires root unless `-u` is given, reads the version file with `read_version_numbers` at 0x10003770, then either opens `/dev/opengl` and counts boards with ioctl 0x65 (`open_graphics`, 0x10005890) or opens the device file named by `-u` read-write, and for each board visits the compositor behind it with `gfx_probe_compositor` (0x10005980). A board is skipped unless the compositor is on port 0. The flash is reached through the compositor's `CHIC` chip registers (chip address bytes 0xd4 to write and 0xd5 to read, wrappers `write_chic_reg` at 0x10003d00 and `read_chic_reg` at 0x10003bb0): register 0 selects a flash region (0x1e0000 for the version area, a start address for an image), register 1 starts a sequence, registers 3 and 4 write and read words and register 5 carries busy bits that `read_flash_versions` (0x10003dd0) tests before it reads two version records. `update_xilinx` at 0x10004a70 compares each image's version in the file with the record in the flash through `cmp_needs_replacing` (0x100035c0) and calls `flash_xilinx` at 0x10004e50 for each stale one; `write_flash_versions` at 0x10004510 then rewrites the version area.
- `usr/gfx/STINGRAY/bin/cmp_flash_all`: **established.**
  A shell script of 242 bytes that runs the updater on every compositor.
  The test at offset 55 asks whether the directory `/hw/compositor` exists.
  The loop at offset 84 runs the updater with `-u` and each directory entry, after an "=== Flashing" banner, and passes the caller's arguments on.
  The branch at offset 195 runs the updater once with the arguments alone, so a host without the USB compositor device takes the graphics-device path of `main`.
- `usr/gfx/ucode/STINGRAY/xlx/VERSION`: **established.**
  Three lines of text, 54 bytes: a date stamp (Thu Jul 20 18:33:08 PDT 2006) and one line per firmware image in the layout `read_version_numbers` parses with the format `%s 0x%x %d %d %s`. `ccx.mcs` is written at flash start address 0x00000 as FPGA 0, configuration 0, version 1.2.2; `ctx1.mcs` at 0x188000 as FPGA 1, configuration 0, version 1.0.0. The comparison in `cmp_needs_replacing` uses the version text and the FPGA and configuration numbers from these lines. The two images fit their slots: `ccx.mcs` has 823440 bytes of data, ending at 0xc9090, below the start of `ctx1.mcs`.
- `usr/gfx/ucode/STINGRAY/xlx/ccx.mcs`: **established.**
  The image for the compositor's CCX logic (the name `ccx.mcs` is the one the version file and `flash_xilinx` use), in an Intel-style hexadecimal text format with 16 data bytes per record. 51465 data records give 823440 bytes (the highest address is 0xc9090) with no gaps; 13 segment-address records advance the base and one end record closes the file. Every record's checksum is valid. The bytes have their bits reversed within each byte, which is how the flash is loaded one bit at a time: reversing them gives the sync word 0xAA995566 at +4 after the 0xFFFFFFFF padding. After the sync the stream is a Xilinx FPGA configuration packet stream: a command write of 7 (reset the CRC), the frame-length register set to 0x26, the option register to 0x803f2d, register 6 to 0x1c6, command 9 and a zero frame address followed by a data block of 190593 words, six more frame-address writes (0x2020000, 0x2040000 and four more up to 0x20c0000) each with its own data block, and the CRC and a final command 3. Counting every packet, the data words total 205803. No write to the device-identity register occurs anywhere in the stream, so the file names no part number. The register and command numbers match the public Virtex-II family configuration layout (**inferred**, from the published configuration guide rather than from the file).
- `usr/gfx/ucode/STINGRAY/xlx/ctx1.mcs`: **established.**
  The image the version file calls FPGA 1, in the same record format as `ccx.mcs` but much smaller: 4923 data records of 16 bytes, 78756 bytes, two segment-address records and one end record. The bit order, the sync word at +4 and the first packets are the same as in `ccx.mcs`, with the frame-length register at 0xb instead of 0x26, which suggests a smaller target device (**inferred**). It holds five frame-address blocks (frame addresses 0, 0x2020000, 0x2040000, 0x2060000 and 0x2080000) of 19644 words in all, then the CRC, a command 5 and a control-register write of 0x100. As with `ccx.mcs` there is no identity-register write. The assignment of this image to the CTX logic follows the name `ctx1` and the sting tool's `ctx_config` routine, not a field in the file (**inferred**).
- `usr/gfx/ucode/STINGRAY/vfo/README`: **established.**
  A text listing of seven of the eight compositor format files (the serrated stereo variant has no block), one block per format in the order 1280x1024 at 60, 75 and 96, 1600x1200 at 60, 1920x1200 at 60, 1280x1024 at 96s and 1280x1024 at 72; the stereo block has two field sections. Each block gives the total and active lines and pixels, frame rate, fields and swaps per frame, pixel clock and period, a hardware pixel rounding of every 4 pixels, the line length and frequency, the horizontal sync, back porch, active and front porch in pixels and microseconds with the line they are measured on, and the vertical sync, sync pulse, back porch, active and front porch for each field, with the eye each stereo field carries. Its numbers agree with the fields of the matching files: for 1280x1024_60 it gives 1680 by 1066 totals, a 107.453 MHz clock, and 120, 240 and 40 pixel horizontal parts, the values in the `STINGRAY/vfo/1280x1024_60.vfo` row of the format table.
