# Inventory

Generated by `scripts/inventory.py` from the files listed in `scripts/inventory.json`. Do not edit the TSV files by hand: change the script or the config, or the docs they are checked against, and regenerate.

Run it where the MIPS binutils and `pyelftools` exist (`AGENTS.md` section 5):

    scripts/inventory.py

It reads `root/` (gitignored, see `IRIX_FILES.md`), the prose in `docs/*.md` and `ucode/*.md`, and the headers (`*.h`, `*/include/*.h`). `docs/coverage.md` has its measured table rewritten between the `inventory:begin` and `inventory:end` markers.

## Status

- `documented`: the name or value appears on a line that explains it: at least 6 plain words of prose, or 4 in a table row or header comment (names in backticks, hex values and `snake_case` words are not counted as words).
- `named-only`: it appears only on shorter lines, such as a list of names.
- `undocumented`: it appears nowhere in those files.

The doc and section columns give the best hit. A plain lower-case function name ("move") counts only inside backticks or a header, so English words do not match. Hex values must sit on a line or under a heading that mentions a register, offset, block, word, command, FIFO, ioctl and so on. The status measures mention, not correctness; a documented row can still have unknown fields.

## Files

| File | One row per | Built from |
|---|---|---|
| `binaries.tsv` | distinct in-scope file (by SHA-256) | the globs in the config; `builds` lists which releases carry the file |
| `functions.tsv` | function name | `nm` (symtab and dynsym), the SGI `.debug_funcnames` section (static functions), the o32 `.mdebug` procedure table, and, for raw PROM and `ide`, names found by pattern in the image. Stripped files with no symbols contribute nothing: see the `note` column of `binaries.tsv` |
| `mmio.tsv` | board offset or display address | disassembly of the board kernel objects. The board record's PIO base (a load from record +824) is followed through constant offsets, 32/64-bit stores and loads. Display addresses come from header words stored to the display FIFO port and from loads in the read-back window |
| `tokens.tsv` | command-FIFO word, and one row per block id | constants that `lui`/`ori`/`li`/literal-pool loads build and `sw`/`sd` store, in the board kernel objects, every libGLcore build and the X module, filtered to the three word families of `BUZZ.h` (class-1, attribute, sequencer-register) |
| `ioctls.tsv` | ioctl number | the kernel's private and resource-manager dispatch tables (from `.rel.data` relocations), plus `0x6f64xxxx` constants built in user code. `user_functions` lists the callers |
| `ucode.tsv` | microcode routine | each distinct microcode image: record 0, every record five after an end mark, and the entry list libGLcore sends (`scripts/buzz_ucode_disasm.py`) |
| `summary.tsv` | inventory | the counts and percentages shown in `docs/coverage.md` |

## Blind spots

- `mmio.tsv` follows constants within a function. A base or offset passed to a callee, loaded from a table or computed in a loop is missed; the pass 10 note in `docs/kernel.md` lists the callees known to take a base. The X module and libGLcore reach the board through mappings and ioctls, not through the board record, so they are scanned for command words and ioctls only.
- `tokens.tsv` holds only words built from constants. Words loaded from shadow memory or computed are absent. A class-1 word is a row of its own, and its block id is a second row, so a block can be documented while one of its words is not.
- `ucode.tsv` marks routines by the end-mark convention of `ucode/buzz_isa.md`, which is itself inferred; the status looks for the record number near the words entry, routine or record.
- `functions.tsv` names a symbol once however many builds carry it; `binary_ids` says where. Symbol presence is not an executable-code measure: an alias or a stub counts as a function.
- The microcode image bodies, `.vfo` timing files and compositor data are data, not code, and have no rows here.
