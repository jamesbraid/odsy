# Shared kernel objects around the VPro driver

The driver archive `odyssey.a` is linked with generic graphics objects of the IP30 and IP35 kernels. Release IRIX 6.5.30m; each object is a relocatable MIPS64 file. These entries are **inferred** unless they say **established**: the routine lists, sizes and the cross-references between objects were read from the symbol tables and relocations of the files, and the roles come from what the routines import and export, not from reading every body. Per-routine readings of the generic code are in `docs/kernel-functions.md` where they exist. 

- `usr/cpu/sysgen/IP30boot/gfx.o`: **inferred.**
  The generic graphics device layer of the IP30 kernel, 53712 bytes, 62 routines. It keeps the tables of graphics groups (`init_gfx_group_table` at 0x124, `gfx_group_create` at 0x240) and graphics threads (`init_gthread_table` at 0x3cc, `gthread_create` at 0x46c), registers a board (`GfxRegisterBoard` at 0xa64, which `odsy_attach` imports), adds its hardware-graph edge (`GfxAddHwgraphEdge` at 0xb48), opens and closes the device (`gfxopen` at 0x1fb8, 1148 bytes; `gfxclose` at 0x249c, 1396 bytes), dispatches the device ioctls in `gfxioctl` (0x2b48, 2004 bytes), carries the pipeline-scheduler hooks (`gfx_frs_install` at 0x3424) and converts 32-bit callers' argument blocks (`irix5_to_gfx_getboardinfo_args` at 0x34cc). Six of the routines it defines are imported by the IP30 `odyssey.a`: `GfxBoardInitSema`, `GfxKiller`, `GfxRegisterBoard`, `gfx_fault`, `gthread_find` and `gthread_scan`.
- `usr/cpu/sysgen/IP30boot/gfxs.a(gfx.o)`: **established.**
  The copy of the generic graphics layer inside the support archive `gfxs.a`, 53716 bytes: it has the same 62 routines as the loose `gfx.o` and every one has identical code (equal hashes); the four extra bytes lie outside the routines.
- `usr/cpu/sysgen/IP35boot/gfx.o`: **established.**
  The IP35 build of the graphics layer, 53720 bytes. Of its 62 routines, three differ in code from the IP30 build: `gfxopen`, `gfxclose` and `gfxioctl`. The IP35 `odyssey.a` imports eight of the routines this object defines (the IP30 six plus `GfxAddHwgraphEdge` and `gthread_find_gfxp`).
- `usr/cpu/sysgen/IP35boot/gfxs.a(gfx.o)`: **established.**
  The IP35 copy inside `gfxs.a`, 53732 bytes, with the same 62 routines as `IP35boot/gfx.o` and identical code in each.
- `usr/cpu/sysgen/IP30boot/gfxs.a(gfx_flow.o)`: **inferred.**
  The graphics flow-control credit manager of the IP30 kernel, 16516 bytes, 22 routines. `gfx_flow_alloc` (0x178, 512 bytes) and `gfx_flow_dealloc` (0x384) give a board a share of the host's write-response credits, `gfx_flow_attach_me` (0x53c) and `gfx_flow_detach_me` (0x620) bind a graphics process to its board's pipe, and the getters `gfx_flow_credit_tnum_get`, `gfx_flow_credit_total_get`, `gfx_flow_credit_bias_get` and `gfx_flow_credit_count_get` report the transaction number, total, bias and count the driver programs into the board. `gfx_flow_disable_heart_fc` and `gfx_flow_enable_heart_fc` (8 bytes each at 0x6f4 and 0x6fc) are empty on this build. Every routine of this object is read in full in [kernel-flow-control.md](kernel-flow-control.md).
- `usr/cpu/sysgen/IP35boot/gfxs.a(gfx_flow.o)`: **established.**
  The IP35 build of the credit manager, 14836 bytes. It has 16 routines to the IP30 build's 22: the pipe-head routines (`gfx_flow_pipe_head`, `gfx_flow_pipe_head_init`), `gfx_flow_credit_count_set`, the two heart flow-control routines and `gfx_flow_clean_up_other_gfxp` are absent, and the 14 routines they share all have different code. The IP35 `gf_OdsyInitialize` calls `gfx_flow_alloc` at 0x1878 with the `odyssey_dwcredits` value multiplied by 8. The 14 shared routines and the init routine are read in full in [kernel-flow-control.md](kernel-flow-control.md).
- `usr/cpu/sysgen/IP35boot/gfxs.a(klconfig.o)`: **inferred.**
  The IP35 routines that choose the VGA-console pipe from the hardware inventory, 11492 bytes, five routines: `find_gfxpipe` (0x0), `prom_has_vga_support` (0x330, 56 bytes), `find_vga_pipe` (0x368, 800 bytes), `find_vga_noprom_pipe` (0x688, 1140 bytes) and `klcheck_vga` (0xafc, 84 bytes). It imports `get_nasid`, `find_lboard_slot_class`, `find_lboard_class`, `find_first_component`, `find_component` and `chk_for_pebrick` to walk the machine's board and component records, keeps the lists named `graphics_pipe_list` and `vga_pipe_list`, and fails with the message "can't alloc vgap" when `kmem_alloc` returns nothing. The IP30 kernel has no equivalent object.
- `prom_has_vga_support` (`klconfig.o`, offset 0x330, 56 bytes): **established.**
  Build: `usr/cpu/sysgen/IP35boot/gfxs.a(klconfig.o)`.
  Gates the firmware-list path of `find_vga_pipe`. It loads two pointers from the read-only pool (`.lit8` offsets 8 and 16, the uncached addresses 0x90000000180000a0 and 0x90000000180000a4), reads one 32-bit word through each, and returns 1 only when the first word is at least 6 and the second is at least 171 (`sltiu` against 6 at 0x340 and against 171 at 0x348, both unsigned). Every other case returns 0; it calls nothing and touches no argument. Read in full.
- `klcheck_vga` (`klconfig.o`, offset 0xafc, 84 bytes): **established.**
  Build: `usr/cpu/sysgen/IP35boot/gfxs.a(klconfig.o)`.
  Tests whether one function slot behind a bridge is a VGA-class display device and, if so, clears the low two bits of one register byte. The address is a0 + (a1 << 12) + (a2 << 8) + 0x20000 (0xb00 to 0xb10); the word at +8 of it has its top byte (bits 31:24) compared with 3 at 0xb24 and the byte below (bits 23:16) tested for zero at 0xb2c. A mismatch on either returns 0. On a match the byte at +7 is loaded, ANDed with 0xfc, stored back (the `sb` at 0xb4c sits in the delay slot of the return) and the address is returned. It calls nothing. Read in full.
- `find_gfxpipe` (`klconfig.o`, offset 0x0, 816 bytes): **inferred.**
  Build: `usr/cpu/sysgen/IP35boot/gfxs.a(klconfig.o)`.
  Returns the board record of the a0-th display board of the local node, or 0. It calls `get_nasid` at 0x14, forms the node's window address (0x9600000000000000 plus nasid << 33, ORed with 0x2000), loads the doubleword at +208 of it and returns 0 unless the 32-bit word that points at is 0x58464552 (compare at 0x40). A list head at `.sdata` offset 0 (doubleword) decides the path. When it is non-null, the routine steps a0 times along the link at +72 of each node (loop at 0xb8 to 0xcc, 0 when the list ends first) and then calls `find_lboard_slot_class` at 0x12c with class 0x50, passing the node's byte at +71 as the slot. When the list is empty it walks 128 halfword entries at +128 of the node's pointer (0x184, entries of -1 skipped), resolves each entry with `find_lboard_class` (0x1cc and 0x248, class 0x50) and `find_first_component` (0x25c, type 0xa), calls `chk_for_pebrick` (0x2f8, 0x310) for entries whose table word has type bits 0xc000, and links each component record it finds into the list in order of a 12-bit key in bits 19:8 of the word at record +68 (insertion loop 0x1f0 to 0x218), after setting bit 2 of the byte at +2 and building that word from the low nibble of the byte at +10 and the halfword at +14 shifted left 8.
- `find_vga_pipe` (`klconfig.o`, offset 0x368, 800 bytes): **inferred.**
  Build: `usr/cpu/sysgen/IP35boot/gfxs.a(klconfig.o)`.
  Returns the a0-th VGA-capable display component of the local node, or 0, using the firmware's own inventory. It calls `get_nasid` at 0x378, builds the node window address as `find_gfxpipe` does and returns 0 unless the word behind the doubleword at +208 is 0x58464552 (0x3a8). It then calls `prom_has_vga_support` at 0x3c8; when that returns 0 it hands the same index to `find_vga_noprom_pipe` (call at 0x678, result returned). Otherwise it reads the list head at `.sdata` offset 8 and, when set, follows the link at +56 up to a0 times and returns that node (0 past the end; loop 0x3e4 to 0x3f0). An empty list is built only while the word at `.sdata` offset 16 (initial value 1) is still non-zero: the routine clears that word (0x44c), walks 128 halfword entries at +128 of the node's pointer, skips -1 entries, calls `chk_for_pebrick` (0x63c) for entries whose table word has type bits 0xc000, resolves the others with `find_lboard_class` (0x4d0 and 0x50c, class 0x70), `find_first_component` (0x520) and `find_component` (0x588), both for type 0x2f, and writes the scan index as a halfword at +80 of each component it keeps, then chains it through +56 (store at 0x580, or into the list head at 0x620 when the list was empty). It also fills the doublewords at +64 and +96 and the bytes at +82, +84 and +86 of those records. With the flag already clear and no list it returns 0.
- `find_vga_noprom_pipe` (`klconfig.o`, offset 0x688, 1140 bytes): **inferred.**
  Build: `usr/cpu/sysgen/IP35boot/gfxs.a(klconfig.o)`.
  Returns the a0-th VGA display function of the local node, or 0, by probing the bridges itself, and is used when the firmware is too old to publish the list. It calls `get_nasid` at 0x694, checks the 0x58464552 word as `find_vga_pipe` does and returns 0 on a mismatch (0x6c4). It shares the list head at `.sdata` offset 8 with that routine and walks it the same way (loop 0x6d4 to 0x6e0). An empty list is built once, guarded by the word at `.sdata` offset 20 (initial value 1, cleared at 0x740). The scan covers 128 halfword entries, resolves each with `find_lboard_class` (0x804 and 0x84c, class 0x70), `find_first_component` (0x860) and `find_component` (0x880), both for type 5, and keeps components whose byte at +57 is 7. For each of the component's eight slots (the 32-bit value 72 bytes into the component plus 8 per slot) it calls `klcheck_vga` (0x978), and for each hit it takes a 144-byte record from `kmem_alloc` (0x98c, flag 1). Before the slot loop it forms a base address from the board's halfword at +32 shifted left 33 and the byte 32 bytes into the component, shifted left 24 (0xa18 when bits 13:12 of the halfword at component +36 are 0, 0xa48 when they are 1, which adds 0x800000); that base is the first argument of `klcheck_vga`, and the slot number and the low byte of the shifted word at component +36 are the others. The record stores the board at +72, that base at +64, the `klcheck_vga` result at +96, the scan index as a halfword at +80 and zeroes at +56 and +104 to +128. It sets the byte at +85 to 1 when the halfword at component +10 is 0xd102 or 0xd112. When the allocation fails, the message "can't alloc vgap" goes to `cmn_err` at 0xae0, and the code then carries on to the stores at 0x9a0 with a null record pointer in s2 rather than returning.
- `usr/cpu/sysgen/IP30boot/gfxs.a(gfx_debug.o)`: **established.**
  A debugging object of 1220 bytes with a symbol table of five entries (all file and section symbols) and no routine, only the debug records of its source file `gfx_debug.c`. It contributes no code to the link.
- `usr/cpu/sysgen/IP30boot/gfxstubs.a(gfxstubs.o)`: **established.**
  The stand-ins used by a kernel built without graphics: 18 routines of 8 bytes each (`gfx_exit` at offset 0, `gfx_disp` at 0x8, `gfx_earlyinit`, `tp_init`, `tp_dogui`, `tpcons_write`, `gfx_fault`, `rrmSuspend`, `rrmResume`, `gfx_shcheck`, `gfx_shdup`, `gfx_shalloc`, `gfx_shfree`, `shmiq_sproc`, `initkbdtype`, `gfx_frs_valid_pipenum`, `gfx_frs_install` and `gfx_frs_uninstall`), each a return and its delay slot. The set is the entry points the generic kernel calls whether or not a graphics driver is configured; that they are only used in a graphics-free kernel is **inferred**.
- `usr/cpu/sysgen/IP35boot/gfxstubs.a(gfxstubs.o)`: **established.**
  The IP35 copy of the stub object, 7300 bytes against 8532 for IP30, with the same 18 routines and identical code in each. The 1232-byte size difference is outside the routines, which are identical (where it sits was not located).
- `usr/cpu/sysgen/IP30boot/odysseystubs.a(odysseystubs.o)`: **established.**
  The 3476-byte stub object for a kernel without the VPro driver, one routine (`odsy_earlyinit`, a return with a zeroed result) and the defaults of the three driver tunables; see [kernel-config.md](kernel-config.md) for the words it holds.
- `usr/cpu/sysgen/IP30boot/rrm.o`: **inferred.**
  The resource manager of the IP30 kernel, which arbitrates a graphics board's clip regions, swap buffers, retrace and video sync between processes, 63904 bytes, 72 routines. The entry `RRM_Dispatch` takes the manager's ioctl requests, `RRM_OpenRN` and `rrmCloseRN` (796 bytes) create and drop a resource, `RRM_SwapBuf` (668 bytes) queues a swap, `rrmSuspend` (936 bytes) and `rrmResume` (1180 bytes) bracket a context switch, and the `rrmValidate*` routines (`rrmValidateRetrace`, `rrmValidateBuffer`, `rrmValidateMGRSwapBuf`, `rrmValidateVideoSync`) call into the driver's validate hooks. Six of its routines are imported by the IP30 `odyssey.a` (`RRM_CheckValidFault`, `rrmGenlockNotify` and the four `rrmValidate*` entries).
- `usr/cpu/sysgen/IP35boot/rrm.o`: **established.**
  The IP35 build of the resource manager, 63896 bytes with the same 72 routines. Three differ in code from the IP30 build: `rrmResume` (1196 bytes against 1180), `rrmValidateMyPcx` and `RRM_SwapBuf`.
- `usr/cpu/sysgen/IP30boot/kernel.o`: **inferred.**
  The IP30 kernel proper, 577112 bytes with 726 routines in the inventory (839 function symbols): the platform and generic code that every driver links against, with no routine of its own for the VPro board. The IP30 `odyssey.a` takes 13 of its routines: `assfail`, `bcopy`, `bzero`, `copyin`, `copyout`, `debug`, `dki_dcache_wb`, `pte_cachebits`, `splhi`, `splx`, `strlen`, `us_delay` and `wbflush`.
- `usr/cpu/sysgen/IP35boot/kernel.o`: **inferred.**
  The IP35 kernel proper, 1288752 bytes with 1318 routines. Beside the same generic services, the IP35 `odyssey.a` takes seven platform routines the IP30 driver does not use: `cnodemodule_lookup`, `find_first_component`, `get_chimera_type`, `get_nasid`, `get_xbow_peer`, `hub_set_piomode` and `hub_widget_flags_set`, which locate the board's node and set the widget's PIO mode. `install_gfxintr` (0x20c08, 108 bytes) is the one routine of this object whose name carries graphics.
- `usr/cpu/sysgen/IP30boot/tport.a(tport.o)`: **inferred.**
  The textport (console terminal) streams driver of the IP30 kernel, 23588 bytes, 22 routines. `tp_wput` (0x244, 1156 bytes) handles the output stream, `tp_rcv`, `tp_rsrv` and `tp_rx` the input side, `tp_init` (0xfc8, 456 bytes) sets the unit up and `tpcons_write` (0xf88) writes console text; `gfx_earlyinit` (0x1230, 36 bytes) lives here too. It draws through the board's own textport routines in `odsy_tport.o`.
- `usr/cpu/sysgen/IP35boot/tport.a(tport.o)`: **established.**
  The IP35 textport driver, 23668 bytes with the same 22 routines; `gfx_earlyinit` is the only routine whose code differs from the IP30 build.
