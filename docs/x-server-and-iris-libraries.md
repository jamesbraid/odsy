# X server, GLX module and the IRIS GL libraries

Five shared programs sit between an application and the VPro board without containing board code of their own. Release IRIX 6.5.30m; all five are N32 or O32 images except where stated. Counts, imports and entry addresses are read from the dynamic symbol tables and section headers (**established**); the roles are **inferred** from what each file exports and imports unless the entry says it read the body. The X module that does reach the board, `usr/lib/X11/dyDDX/odyssey.so`, is covered in `docs/odyssey-so-functions.md`.

- `usr/gfx/arch/GENERIC/Xsgi`: **established** for board discovery and module loading, **inferred** for the rest.
  The X server executable for all the SGI display families, an N32 `ET_EXEC` image of 3120928 bytes with 3735 exported names and 3158 imports, needing only `libm.so` and `libc.so.1`; its entry is `main` at 0x10218270 (5600 bytes) and the request loop is `Dispatch` at 0x101a9fa0 (6956 bytes).
  The routine `ddxFindAvailableBoards` (0x10082870, 972 bytes, whole body read in the decompilation) opens `/dev/opengl`, asks the board count with ioctl 0x65, warns when there are more than 16 boards and keeps 16, then fetches each board's record with ioctl 0x66, first with a 40-byte request to learn the record size and then with an allocation of that size ("Get board info (short) failed", "Alloc of board info failed" and "Get board info (long) failed" are its error texts). It keeps the records in a per-board table and closes the device.
  The display driver for each board is a separate module: `ddxMakeDynamicModulePath` (0x10080080, 124 bytes) builds `<dir>/<name>.so` where `<dir>` is the `DYNAMICDDXDIR` environment variable or `/usr/lib/X11/dyDDX`, and `ddxSetLoadType` (0x100cc040) reads the options `-dynamic` and `-static`. For a VPro board that module is `odyssey.so`.
  `glxScreenInit` (0x100620f0, 456 bytes) copies a 132-byte per-screen record for the GLX extension, and the server's video-control extension is initialised by `XSGIvcScreenInit` (0x100d31d0).
- `usr/lib/X11/dyDDX/glx.so`: **inferred.**
  The GLX extension of the X server, a loadable module of 646360 bytes with 1061 exported names, 528 of them `__glX` routines, and 1542 imports. It needs `libGLcore.so` and `libm.so`, so the server process runs the board renderer inside itself for indirect rendering.
  Its init entry `__glXExtensionInit` is at 0x29a60f0 (1076 bytes), `__glXScreenInit` at 0x29be6d0 (264 bytes), `glxInitDispatch` at 0x29e15c0 (328 bytes) and `glxThreadInit` at 0x29c3ff0 (140 bytes). The request handlers come in pairs, `__glXDisp_*` for same-byte-order clients and `__glXDispSwap_*` for swapped ones, for example `__glXDisp_LoadMatrixf` at 0x29e0580 (64 bytes) and `__glXDispSwap_LoadMatrixf` at 0x299e7d0 (240 bytes).
- `usr/gfx/arch/IGLOO/libgl.so`: **inferred.**
  The O32 IRIS GL library, 1747724 bytes, 3811 functions, 3567 exported names, 406 imports, soname `libgl.so`. It needs `libGL.so`, `libGLU.so`, `libm.so`, `libXmu.so`, `libXsgivc.so`, `libX11.so.1`, `libXi.so`, `libXext.so` and `libc.so.1`, which says it is layered on OpenGL and X, with no board access of its own.
  The names that carry the layering are `__igloo...` (`__iglooLoadInterface` and `__iglooInitProcs` pick up the OpenGL entry points; `__iglooInitializeOpenglState` sets up the OpenGL state an IRIS GL window needs), beside the IRIS GL calls themselves (`winopen`, `ginit`, `gconfig`, `swapbuffers`, `lrectwrite`, `blendfunction`).
- `usr/gfx/arch/IGLOO32/libgl.so`: **inferred.**
  The N32 build of the same library, 1833076 bytes, 3811 functions, 3576 exported names, 405 imports and the same nine needed libraries. It carries DWARF (the `.debug_info` and `.debug_line` sections are present, where the O32 file has none), and its routines are at these addresses: `winopen` 0xec6319c (200 bytes), `ginit` 0xec641cc (172 bytes), `gconfig` 0xec690f0 (180 bytes), `swapbuffers` 0xec6fef8 (180 bytes), `lrectwrite` 0xec6baa0, `blendfunction` 0xec71e4c, `__iglooLoadInterface` 0xeca40c0 (408 bytes) and `__iglooInitProcs` 0xeca47d0 (476 bytes). The eleven IRIS GL calls listed here are 172 to 200 bytes each except `color` and `v3f` (68 bytes), which suggests thin wrappers over the OpenGL path (**inferred**; the bodies were not read).
- `usr/lib32/libfm.so`: **inferred.**
  The IRIS GL font manager, an N32 library of 683872 bytes with 791 functions, 610 exported names (42 start with `fm`) and 140 imports, soname `libfm.so`. It needs `libgl.so`, `libm.so` and `libc.so.1`, so it draws text through the IRIS GL library and reaches no board directly. The font calls are small: `fminit` at 0xee2cbe0 (88 bytes), `fmfindfont` at 0xee2c838 (108 bytes), `fmscalefont` at 0xee2cea4 (132 bytes), `fmsetfont` at 0xee2cf88 (96 bytes), `fmprstr` at 0xee2cdd8 (108 bytes) and `fmgetfontinfo` at 0xee2ca08 (116 bytes).
