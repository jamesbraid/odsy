# Resource-manager routines, one entry each (masks, validation and waits)

Release IRIX 6.5.30m, `usr/cpu/sysgen/IP30boot/rrm.o`. The pane table and set-up routines at the start of the same object are in [kernel-rrm-panes.md](kernel-rrm-panes.md). Labels are **established** (the whole routine was read from the fact sheet and the disassembly of the build the entry names) or **inferred**. Offsets are bytes into the argument record as the code addresses them; where an entry says "the node" it means the first or second argument as stated, and no field name is claimed beyond what the code proves. The `STREAM` routines are callbacks: the pointers to them sit in the object's small-data table (relocations at small-data offsets 0x28 and 0x30), and the plain routines of the same name schedule them with `streams_timeout`.

- `rrmGetResourceMask` (`rrm.o`, offset 0x2168, 8 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Returns the unsigned halfword at +4 of its argument, the node's current resource-mask word. It is a return with the load in the delay slot and touches nothing else.

- `rrmValidateBuffer` (`rrm.o`, offset 0x2abc, 68 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Revalidates a node's buffer through the pane layer, first updating a counter in the record at +120 (argument: the node). It takes the manager object from +72 of the argument; when that object's word at +160 is nonzero it adds its word at +164 to the word at +24 of the record that the argument's pointer at +120 names and stores the sum at +28 of that record. It then calls `validate_pane_buffer` with the pointer at +120 (loaded in the delay slot) and the pointer at +64, and returns that call's result.

- `rrmValidateMGRSwapBufSTREAM` (`rrm.o`, offset 0x4044, 76 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Callback that posts a buffer-swap validation message to a graphics-message sink (arguments: record, swap value). It does nothing when the first argument is null or the pointer at +8 of it is null. Otherwise it builds a message at the start of its own stack frame and calls `GfxIntrMessage` with it. The stores, in issue order, are: zero at message offset 24, zero at 20, the swap value (second argument) at 16, the word 3 at 12, the byte 9 at 8 and the pointer taken from +8 of the first argument at message offset 0 (in the delay slot of the call). It sets no return value of its own, on any path.

- `rrmValidateMGRSwapBuf` (`rrm.o`, offset 0x4090, 72 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Defers the same notification to the streams timer (arguments: record, swap value). With a null first argument or a null pointer at +8 of it it returns at once. Otherwise it calls `streams_timeout` with the address of `streams_monp`, the callback `rrmValidateMGRSwapBufSTREAM`, the constant -100 as its third argument, the record as the callback argument, the swap value zero-extended from its low 32 bits (formed with `dsll32` and `dsrl32` in the delay slot) and a final argument of 0. The return value of `streams_timeout` is returned.

- `rrmGenlockNotifySTREAM` (`rrm.o`, offset 0x40d8, 72 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Callback that posts a genlock event message to the same sink (arguments: record, got-or-lost flag). It returns without a message when the first argument is null or the pointer at +8 of it is null. Otherwise the message on its stack takes, in issue order, the flag at message offset 20, zero at 16, the word 2 at 12, the byte 12 at 8 and the pointer from +8 of the first argument at message offset 0 (delay slot), and `GfxIntrMessage` is called with it. Against `rrmValidateMGRSwapBufSTREAM` the type byte (message offset 8) is 12 instead of 9, the word at message offset 12 is 2 instead of 3, the flag goes to message offset 20 with zero at 16, and nothing is stored at 24. It sets no return value of its own.

- `rrmGenlockNotify` (`rrm.o`, offset 0x4120, 72 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Schedules the genlock callback on the streams timer (arguments: record, got-or-lost flag). It is `rrmValidateMGRSwapBuf` with the other callback: the same null checks on the argument and the pointer at +8, then `streams_timeout` with `streams_monp`, `rrmGenlockNotifySTREAM`, -100, the record, the flag zero-extended from 32 bits and 0, returning that call's result. The IP30 driver's genlock clock-update routine calls it with the record's first word and 1 for got or 0 for lost (see `docs/driver-functions.md`).

- `RRM_CheckValidFault` (`rrm.o`, offset 0x36d8, 96 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Decides whether a request may proceed to the fault check (argument: the request). It reads the flag word at +4. Only when flag bit 2 (mask 4) is clear does it load the doubleword at +8 of the object that the doubleword at +8 of the request points to, and it returns -1 when that value is zero. Every other case continues: flag bit 0 (mask 1) set returns 0 without more work, and flag bit 0 clear calls `RRM_ValidFault` with the request and 0 (set in the delay slot). A negative result of that call returns -1, any other returns 0. The four exits are -1 (word zero), 0 (bit 0 set), 0 (fault check not negative) and -1 (fault check negative).

- `rrmValidateRetrace` (`rrm.o`, offset 0x2e4c, 80 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Marks a node's retrace as validated and wakes its waiter (argument: the node). It takes the spin lock at +104 with `mutex_spinlock`, sets bit 4 (0x10) of the halfword at +6, calls `sv_signal` on the variable at +48 (the store of the halfword sits in the delay slot of that call) and releases the lock with the saved level. It returns what `mutex_spinunlock` returns.

- `rrmValidateMyRetrace` (`rrm.o`, offset 0x2dd4, 120 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Blocks the caller until its retrace has been validated (arguments: unused first argument, the node). It takes the spin lock at +104. The test is the halfwords at +4 and +6: with E the halfword at +4 and V the one at +6, it waits only when bit 4 (0x10) of E & (V xor E) is set, that is when the bit is wanted in +4 and not yet set in +6. Waiting is `sv_wait` on the variable at +48 with 25 as the second argument, the lock address as the third and the saved level as the fourth (the call releases the lock). Without a wait it calls `mutex_spinunlock`. Both paths return 0.

- `rrmSetResourceMask` (`rrm.o`, offset 0x29b4, 192 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Changes the resource mask of a node and drops the board mapping if a resource is gained that is not currently valid (arguments: the caller's node, the target node, the new mask). Under the spin lock at +104 of the target it reads the halfword at +4 (old mask) and the one at +6; when bit 1 (mask 2) of the old mask is set it ORs the result of `pane_validmask`, called with the pointer at +120 of the target, into the +6 value. It unlocks, then computes the bits that are in the new mask and not the old and, of those, the ones missing from the +6 value; if any remain it calls `rrmUnMapGfx` with the caller's node. It takes the lock again, stores the new mask as a halfword at +4, unlocks and returns what `mutex_spinunlock` returns.

- `rrmUnbindProcFromRN` (`rrm.o`, offset 0x13b4, 176 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Detaches a node from the process that bound it (argument: the node). It returns -1 at once when the pointer at +72 is zero. Otherwise it looks up the calling thread's graphics list record only when the pointer at +96 is nonzero and flag bit 3 (mask 8) of the word at +4 is clear: `curthreadhandle`, then `gthread_find` on its result. When that lookup yields a record with a nonzero pointer at +16, it calls `GfxListWriterLock` on that pointer and keeps the returned level in the stack word at 0(sp). It then calls `rrmDoUnMapGfx` with the node and clears the pointer at +72 (the store is in the delay slot of that call, so it happens before the callee runs). If a thread record was found and its +16 pointer is nonzero it calls `GfxListWriterUnlock` with that pointer and the saved level. The return value is 0 on every path past the first check.

- `rrmSwapWait` (`rrm.o`, offset 0x3738, 240 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Blocks the caller until the manager's completed-swap count reaches the node's target (argument: the node). The manager object is the pointer at +72 of the node; its spin lock is at +48. After `mutex_spinlock` the target is the word at +28 of the record that the node's pointer at +120 names, and the count is the word at manager +164. When count plus one is not below the target it unlocks and returns 0. Otherwise it links the node into the manager's wait list, a singly linked list whose head is at manager +168 and whose next pointers are at node +168. The list is ordered by the same +28 target as an unsigned compare: the node goes in front of the first entry whose target is not below its own (the node's next pointer is stored first, the previous link in the delay slot of the `hold_nonfatalsig` call). It then calls `sv_wait_sig` on the variable at node +48 with 30 as the second argument, the manager's lock as the third and the saved level as the fourth. A negative result calls `release_nonfatalsig` and returns -1, any other calls `release_nonfatalsig` and returns 0. The interrupted path does not unlink the node.

- `rrmWaitVideoSync` (`rrm.o`, offset 0x43cc, 220 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Blocks the caller until the display's frame counter hits a chosen phase (arguments: the first record, the node, a divisor N, a remainder K). It returns 22 when N is not above 0, K is below 0 or K is not below N (all signed tests). The manager object is the pointer at +40 of the first argument and its lock is at +48. Under that lock it zeroes the node's pointer at +160, stores N at +144 and K at +148 (as words), and pushes the node on the head of the manager's video-sync list (head at +136, the old head becoming the node's pointer at +160). It then waits with `hold_nonfatalsig` and `sv_wait_sig` on the variable at node +48, 30 as the second argument, the manager's lock and the saved level. A negative wait result returns -1, otherwise 0, after `release_nonfatalsig` on both paths.

- `rrmValidateVideoSync` (`rrm.o`, offset 0x44a8, 320 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Wakes every waiter whose condition is now met, for both wait lists of the manager (argument: the manager object, lock at +48). First pass, the video-sync list at +136 (next pointers at node +160): for each node it picks a counter, the word at manager +128 when flag bit 3 of the word at +4 of the record at node +64 is set and the word at manager +124 when it is clear; if the counter modulo the node's N at +144 (`divu`, with a trap on zero) equals its K at +148, the node is unlinked, the counter is stored at node +152 and `sv_signal` is called on the variable at node +48. Second pass, the swap list at +168 (next pointers at node +168): with the completed count at manager +164 plus one, every leading node whose target (the word at +28 of the record at node +120) is not above that value is signalled, its next pointer cleared in the delay slot of `sv_signal`, and the head at +168 is set to the first node that stays. It unlocks with the level saved at entry and returns what `mutex_spinunlock` returns.

- `rrmSwapUnGroup` (`rrm.o`, offset 0x3ac4, 248 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Takes a pane out of its swap group and frees the group when it empties (arguments: the node, the pane). The group is the pointer at pane +160; the manager object is the pointer at node +40. When the group's word at +4 is nonzero and the byte at pane +176 is zero it stores that word minus one back. It then clears the pane's group pointer and unlinks the pane from the ring formed by the pointers at +168: if the pane's next is not itself, it walks the ring to the predecessor and points it at the pane's next. The group's member count at +0 is decremented and stored. A nonzero count returns it. A zero count walks the table whose entry count is the word at manager +176 and whose base pointer is at +184, clears every 8-byte entry equal to the group, and frees the group with `kern_free`; the return value is then that call's result.

- `irix5_to_RRM_ValidateClip` (`rrm.o`, offset 0x4adc, 208 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Argument-layout converter for the clip-validation request, one of two in the object (the other is `irix5_to_RRM_GetDisplayModes`); the pointer to each is in the small-data table at offsets 0x48 and 0x40. The first argument selects the step. With 0 it sizes the copy: if the word at +0 of the fourth argument is below 56 it calls `kern_malloc` for 56 bytes and stores the result at +16, otherwise it copies the pointer at +8 to +16; in both cases it stores 56 at +4 and returns 0. With a nonzero first argument it reads a 56-byte record from the pointer at +16 of the fourth argument and writes the second argument. The writes, in this order, are the words at 0, 4, 8, 12, 16, 20 and 24 copied across, the word at source +28 zero-extended into a doubleword at destination +32, and the words at source 32, 36, 40, 44, 48 and 52 into destination 40, 44, 48, 52, 56 and 60. It returns 0. The destination is therefore 64 bytes: the 32-bit layout's pointer widened and the six words after it moved up by 8.

- `irix5_to_RRM_GetDisplayModes` (`rrm.o`, offset 0x4bac, 120 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Argument-layout converter for the display-modes request, built on the same two-step pattern as `irix5_to_RRM_ValidateClip`. With a zero first argument it checks the word at +0 of the fourth argument against 12, calls `kern_malloc` for 12 bytes into +16 when it is smaller or copies the pointer at +8 to +16 otherwise, stores 12 at +4 and returns 0. With a nonzero first argument it reads a 12-byte record from the pointer at +16: the word at 0 goes to destination +0, the word at 4 zero-extended to a doubleword at destination +8 and the word at 8 to destination +16. It returns 0. The destination is 24 bytes, the middle word having become a 64-bit pointer.

- `rrmAllocPcxid` (`rrm.o`, offset 0x2e9c, 376 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Assigns a context record a slot number and keeps the manager's context list in least-recently-used order, evicting the oldest when no slot is free (arguments: the node, the context record). The manager is the pointer at node +40. Its word at +20 is a slot count, +24 is the base of a table of 8-byte entries, +32 the tail and +40 the head of a list whose links are at record +88 (previous) and +96 (next). The slot number is the halfword at record +80, where -1 means none. "Owner" below is the test that the doubleword at +8 of the doubleword at node +8 equals the node itself. The names of these fields are **inferred** from the behaviour; the offsets and branches are read from the code.
  A slot count of 1 returns the doubleword at manager +8 and changes nothing. Otherwise the paths are as follows. Record with a slot already: a non-owner returns 0 untouched. An owner returns 0 at once when the record's next link is zero; otherwise it unlinks the record (the head moves to its successor when it had no predecessor) and appends it at the tail, the tail pointer being stored in the delay slot of the return. Record without a slot: a positive count first scans the table from entry 0 for the first zero entry and stores that index as a halfword at +80 (the scan finds nothing and leaves -1 when every entry is nonzero; a count of zero or less skips the scan). A non-owner then returns 0, with the table entry itself left untouched. An owner with a slot now found appends at the tail, or on an empty list (tail pointer zero) makes the record head and tail with both links cleared; both return 0. An owner still without a slot evicts the head record: the head moves to its successor (whose previous link is cleared), the evicted record's slot number is copied into this one, and this record is appended at the tail. That last path returns the evicted record's address, loaded into `v0` just before, and is the only exit other than the count-1 case that does not return 0.

- `rrmCloseRN` (`rrm.o`, offset 0x1bf0, 796 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Detaches a context record from a resource node and frees the record's state (arguments: the node in a0, the record in a1; the manager is the doubleword at node +40, called M). It stores 0 at +56 of the record first. When flag bit 3 (mask 8) of the node's word at +4 is set and the record's byte at +84 is nonzero but its doubleword at +64 is not the node, it returns 0 at once; otherwise, with bit 3 set, it stores the node at record +64. It then takes M's ownership doubleword at +72: when that is not the node it waits on `psema` for the semaphore at M+56 (priority 537), stores the node at M+72 and, while the word at M+104 is nonzero, calls `us_delay` with 2. It adds 1 to the word at M+80 and calls the handler at +72 of the table at node +32 with M, the node and the record. When the node's doubleword at +72 is the record it calls `rrmUnbindProcFromRN` and, if that returns nonzero, logs "rrmCloseRN: ERROR rrmUnbindProcFromRN" through `cmn_err` (small-data string offset 376). Under `mutex_spinlock` on M+48 it removes the record from two chains, the one headed at M+168 (links at record +168) and the one headed at M+136 (links at +160), zeroing the removed record's link. With bit 3 clear it also removes the record from the node's singly linked list at node +64 (entries hold the record at +0 and the next at +8) and frees that entry with `kern_free`. It adds 1 to the halfword at record +0 modulo 0x8000 (the store is in a branch delay slot), calls `unbind_pane` with the pointer at +120 and, when the pointers at +120 and +128 differ, with the one at +128, and zeroes both. It destroys the record's `sv` at +48 and spin lock at +104, sets the byte at +82 to 1, clears M+8 when it equals the record, and, when the halfword at +80 is not -1, zeroes that entry of the 8-byte table at M+24 and takes the record out of the doubly linked list whose end pointers are M+32 and M+40, using the record's links at +88 and +96 unless the doubleword at +8 of the record at node +8 is the node. - `RRM_Exit` (`rrm.o`, offset 0x1f2c, 572 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Process-exit cleanup of a node (argument: the node, a0; M is the doubleword at node +40). With node flag bit 3 clear it walks the singly linked list at node +64: for each entry it takes the record at entry +0, takes the semaphore `RRMcall_sema` indexed by the halfword at record +2 (16 bytes per slot) with `psema` at priority 25, calls `rrmCloseRN` with the node and record, logs "RRM_Exit: ERROR rrmCloseRN" through `cmn_err` (small-data offset 416) if that is nonzero, releases with `vsema`, and reloads the list head. With bit 3 set it takes the record at +72; when that is nonzero and its doubleword at +56 is not the node it takes that record's semaphore, stores 0 in its byte at +84, calls `rrmCloseRN` when its doubleword at +56 is zero and `rrmUnbindProcFromRN` otherwise, and releases. It then scans slots 1 up to `rrm_maxrn` - 1 of the table of 176-byte records (the small-data pointer at gp-30688), and for each record whose doubleword at +56 is the node does the same take, `rrmCloseRN`, error log and release. Last, when M is nonzero and its doubleword at +72 is the node, it stores 0 at M+84, calls `splhi` (the store of 0 at M+80 is in the delay slot), calls the function at +192 of the table at node +32 with the node when that pointer is nonzero, stores 0 at M+72, `vsema` on M+56 and `splx`. It returns 0 on every path.

- `rrmValidateMyPcx` (`rrm.o`, offset 0x3014, 596 bytes): **established.**
  Build: `usr/cpu/sysgen/IP30boot/rrm.o`.
  Gives a context record a hardware context slot when it needs one (arguments: the node in a0, the record in a1; M is the doubleword at node +40). Under `mutex_spinlock` on record +104 it reads the halfwords at +4 and +6. Unless bit 0 of (halfword +4 AND NOT halfword +6) is set it returns 0. Otherwise it adds 1 to the word at M+80 and, when the doubleword at M+8 is nonzero and is not the record, calls `rrmInvalidateRN` with the node, that record and 1. If the halfword at record +80 is not -1 the record already has a slot: it calls `rrmAllocPcxid` and then the function at +128 of the table at node +32 with M, the record and the doubleword at M+8. When it is -1: if the byte at +83 is zero and bit 1 of halfword +4 is set it calls `invalidate_pane` with 2, the word at +4 of the pointer at record +120 and the node, and remembers that; then it calls `rrmAllocPcxid`, and with a nonzero slot calls the function at +120 of that table (M, the slot, the record, M+8) and stores the halfword -1 at slot +80, or with a zero slot calls the same function with slot 0. A table entry at the record's halfword +80 (the 8-byte table at M+24) takes the record when that halfword is not -1. It then adds 1 to the word at +8 of the 32-byte entry of `gfxinfo` chosen by the halfword at process-page address -15456, stores the record at M+8 (delay slot of the lock call) and sets bit 0 of halfword +6 under the record's lock.
